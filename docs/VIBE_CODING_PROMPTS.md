# 바이브코딩 프롬프트 정리본

## 목적
이 문서는 구현 보고서 5번에서 분리한 바이브코딩 프롬프트 산출물이다. 실제 개발은 큰 기능을 한 번에 요청하는 방식이 아니라, 병원 블로그 생성기를 기능 모듈로 잘게 나누고 각 모듈마다 역할, 입력, 처리, 출력, 제약조건, 검증 기준을 명시하는 방식으로 진행하였다.

## 프롬프트 작성 원칙
| 원칙 | 적용 방식 |
|---|---|
| 기능별 분해 | 콘텐츠 생성, 키워드 분석, 스타일/레퍼런스, 이미지/브랜딩, 저장/배포로 나누어 요청 |
| 입력과 출력 고정 | 각 프롬프트마다 사용자가 넣는 값과 화면에 표시될 결과를 먼저 정의 |
| Python 중심 구현 | Streamlit 화면, Python 모듈, DB/API 연동을 기준으로 코드 요청 |
| 의료광고 안전성 | 진단·치료 보장 표현을 피하고 의료진 최종 검토 전제를 포함 |
| 검증 가능성 | 구현 후 테스트 시나리오와 실패 조건을 함께 요청 |

## P-01. 전체 아키텍처 프롬프트
```text
너는 Python/Streamlit 기반 서비스 프로토타입을 설계하는 개발자다.
프로젝트는 “개원의를 위한 병원 마케팅 블로그 생성기”이다.
목표는 개원의가 직접 작성하는 느낌의 신뢰도 높은 블로그 글을 만들고, 키워드 분석·썸네일·워터마크까지 한 흐름에서 처리하는 것이다.

필수 조건:
1. 구현 언어는 Python 중심으로 한다.
2. UI는 Streamlit으로 구성한다.
3. 기능은 app.py, pages/, src/naverblog/, scripts/로 분리한다.
4. API 키는 코드에 직접 넣지 않고 환경변수 또는 Streamlit Secrets로 처리한다.
5. 의료정보는 일반 안내이며 최종 발행 전 의료진 검토가 필요하다는 전제를 유지한다.

출력:
- 전체 폴더 구조
- 각 파일의 책임
- 입력→처리→출력 데이터 흐름
- 먼저 구현할 MVP 기능과 나중에 확장할 기능 구분
```

## P-02. 콘텐츠 생성 모듈 프롬프트
```text
병원 블로그 글 생성 모듈을 설계하고 Python/Streamlit 코드 구조를 제안해줘.

입력:
- 진료과
- 지역명
- 증상 또는 검사 키워드
- 카테고리 프리셋
- 페르소나
- 글 유형
- 의사가 직접 강조하고 싶은 코멘트

처리:
1. 입력값을 정리하여 프롬프트 변수로 만든다.
2. 병원 스타일 가이드와 레퍼런스 글을 함께 반영한다.
3. 환자 눈높이의 정보형 글 구조로 Markdown 초안을 생성한다.
4. 네이버블로그에 붙여넣기 쉬운 HTML로 변환한다.
5. 본문 중간에 이미지 삽입 위치 마커를 표시한다.

출력:
- 제목 후보
- Markdown 본문
- HTML 본문
- 이미지 삽입 위치
- 의료진 검토 안내 문구

주의:
- 완치 보장, 100% 효과, 부작용 없음 같은 표현은 사용하지 않는다.
- 병원 홍보보다 환자가 이해할 수 있는 설명형 문체를 우선한다.
```

## P-03. 프롬프트 파이프라인 모듈 프롬프트
```text
src/naverblog/pipeline.py 역할을 설계해줘.

요구사항:
1. 검색 스킬, 키워드 스킬, 스타일 스킬, 레퍼런스 스킬을 순서대로 실행한다.
2. 각 스킬의 결과를 하나의 context 객체로 모은다.
3. Jinja2 템플릿을 사용해 최종 LLM 프롬프트를 조립한다.
4. LiteLLM을 통해 선택한 모델에 요청한다.
5. 생성 결과를 Markdown과 HTML로 분리해 반환한다.
6. prompt_used와 output을 DB에 저장할 수 있도록 Generation 모델에 맞춘다.

검증:
- 스킬이 비활성화되어도 기본 글 생성은 동작해야 한다.
- LLM 호출 실패 시 사용자에게 원인을 알 수 있는 오류 메시지를 보여줘야 한다.
```

## P-04. 키워드 분석 모듈 프롬프트
```text
병원 블로그 발행 전략을 위한 키워드 분석 모듈을 구현해줘.

입력:
- 기준 키워드 1개
- 비교 키워드 여러 개
- 분석 기간
- 기기, 성별, 연령대 옵션

필수 지표:
1. 월간 PC 검색량
2. 월간 모바일 검색량
3. 총 검색량
4. 경쟁도
5. 블로그 발행수
6. 카페 발행수
7. 콘텐츠 포화지수
8. 키워드 등급 S/A/B/C/D
9. 연관 키워드
10. 주제 클러스터
11. 해시태그
12. 검색 트렌드
13. 성별/연령대 인구통계
14. 스마트블록 구성

출력 화면:
- 핵심 지표 카드
- 키워드 등급 배지
- 비교 표
- 트렌드 그래프
- 스마트블록 분석 결과
- CSV 다운로드

판단 기준:
- 검색량은 높고 포화지수가 낮은 키워드를 우선 추천한다.
- 경쟁도가 지나치게 높은 키워드는 대체 키워드를 함께 제안한다.
```

## P-05. 스타일 가이드·레퍼런스 관리 프롬프트
```text
병원 블로그가 대행사 글처럼 보이지 않도록 스타일 가이드와 레퍼런스 글 관리 기능을 만들어줘.

스타일 가이드 기능:
- 공통 글쓰기 원칙 편집
- 카테고리별 문체 편집
- 새 카테고리 추가
- 저장 후 글 생성 프롬프트에 자동 반영

레퍼런스 글 기능:
- 제목, 카테고리, 본문, 링크 저장
- 기존 글 목록 표시
- 수정/삭제 가능
- 새 글 생성 시 관련 레퍼런스를 요약해 context로 전달

출력:
- 병원 고유 문체 규칙
- 참고 글 요약
- 생성 프롬프트에 삽입할 reference_context
```

## P-06. 의료광고 안전성 점검 프롬프트
```text
병원 블로그 글에서 의료광고상 위험할 수 있는 표현을 점검하는 Python 로직을 작성해줘.

위험 표현 예시:
- 완치
- 100% 효과
- 부작용 없음
- 최고
- 유일
- 무조건
- 보장
- 즉시 치료

출력 형식:
- 발견 표현
- 위험 이유
- 대체 표현 방향
- 수정 예시

화면 표시:
- 위험 표현이 있으면 경고 카드로 보여준다.
- 위험 표현이 없으면 “의료진 최종 검토 필요” 안내와 함께 통과 상태를 보여준다.
```

## P-07. 이미지 생성·본문 배치 프롬프트
```text
블로그 글 주제에 맞는 이미지 생성과 본문 배치 기능을 설계해줘.

입력:
- 글 주제
- 진료과
- 원하는 이미지 톤
- 업로드 이미지 목록

처리:
1. 본문 흐름에 맞는 이미지 프롬프트를 만든다.
2. AI 이미지 생성 API를 호출한다.
3. 업로드 이미지와 생성 이미지를 구분해 저장한다.
4. Markdown 본문 안에 [이미지 1 삽입 위치] 같은 마커를 넣는다.

출력:
- 이미지 파일
- 이미지 설명
- 본문 삽입 위치
- HTML 변환 시 이미지 마커 유지
```

## P-08. 썸네일 제작 모듈 프롬프트
```text
병원 블로그용 썸네일 제작 화면을 Streamlit 페이지로 설계해줘.

기능:
- 제목/부제목 텍스트 입력
- 글자 크기, 색상, 위치 조절
- 배경 색상 또는 이미지 업로드
- 템플릿 선택
- 정렬과 여백 조절
- 미리보기
- PNG 다운로드

구현 방향:
- Python에서 기본 썸네일 데이터를 만들고, 브라우저 편집 영역은 Fabric.js 방식으로 처리한다.
- 의료 콘텐츠에 어울리도록 과도한 광고 느낌보다 깔끔한 정보형 디자인을 기본값으로 둔다.
```

## P-09. 워터마크 모듈 프롬프트
```text
이미지와 PDF에 병원 워터마크를 적용하는 모듈을 작성해줘.

입력:
- 이미지 또는 PDF 파일
- 워터마크 텍스트
- 위치
- 투명도
- 색상
- 글자 크기

처리:
1. 파일 유형을 판별한다.
2. 이미지 파일은 Pillow로 처리한다.
3. PDF 파일은 pypdf/reportlab 기반으로 처리한다.
4. 사용자가 선택한 위치와 투명도를 반영한다.

출력:
- 워터마크 적용 파일
- 다운로드 버튼
- 처리 실패 시 오류 메시지
```

## P-10. 데이터 저장·캐시 프롬프트
```text
SQLite/Supabase 기반 데이터 저장 구조를 정리하고 구현 코드를 작성해줘.

테이블:
- personas: 페르소나 정보
- generations: 생성 글, 사용 프롬프트, Markdown, HTML
- blog_styles: 병원 글쓰기 스타일
- blog_posts: 레퍼런스 글
- keyword_cache: 키워드 분석 캐시
- skills: 기능 활성화 설정
- app_config: 앱 설정

요구사항:
- 생성 결과는 나중에 다시 볼 수 있어야 한다.
- 키워드 분석 결과는 일정 시간 캐시해 API 호출을 줄인다.
- API 키는 DB에 저장하지 않는다.
```

## P-11. 배포 프롬프트
```text
이 Streamlit 앱을 GitHub와 Streamlit Cloud로 배포하는 절차를 정리해줘.

필요 파일:
- app.py
- pages/
- src/naverblog/
- requirements.txt
- packages.txt
- runtime.txt

절차:
1. GitHub에 최신 코드를 push한다.
2. Streamlit Cloud에서 저장소를 연결한다.
3. app.py를 엔트리포인트로 지정한다.
4. API 키는 Secrets에 등록한다.
5. 배포 후 주요 페이지가 열리는지 확인한다.

출력:
- 배포 체크리스트
- 배포 실패 시 확인할 항목
```

## P-12. 구현 검증 프롬프트
```text
완성된 병원 마케팅 블로그 생성기 프로토타입을 테스트해줘.

테스트 시나리오:
1. 강남 내과 감기 몸살 글 생성
2. 완치 보장 같은 위험 표현 점검
3. 키워드 등급과 포화지수 조회
4. 스마트블록 분석 표시
5. 썸네일 제작 후 PNG 다운로드
6. 이미지/PDF 워터마크 적용
7. 레퍼런스 글 저장 후 새 글 생성에 반영
8. GitHub push 후 Streamlit Cloud 배포 확인

결과는 테스트 ID, 입력, 기대 결과, 실제 결과, 수정 필요 여부 표로 정리해줘.
```
