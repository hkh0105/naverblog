# 바이브코딩 프롬프트 정리본

## 목적
이 문서는 구현 보고서 본문에서 분리한 바이브코딩 프롬프트 기록이다. 프롬프트는 단순히 “코드 작성”을 요청하는 방식이 아니라, 역할, 목표, 입력, 출력, 제약조건, 검증 기준을 단계별로 분리하여 실제 개발 산출물로 이어지도록 작성하였다.

## Prompt 1. 프로젝트 맥락 정의
```text
너는 Python과 Streamlit으로 서비스 프로토타입을 설계하는 시니어 개발자다.
프로젝트 주제는 “개원의를 위한 병원 마케팅 블로그 생성기”이다.
이 앱은 의료 진단이나 처방을 대신하지 않고, 병원 블로그 운영을 돕는 마케팅 보조 도구다.

목표:
1. 지역, 진료과, 증상 키워드를 입력받는다.
2. 환자 눈높이에 맞는 병원 블로그 글 초안을 생성한다.
3. 의사가 직접 설명하는 듯한 신뢰도 높은 문체를 적용한다.
4. 의료광고상 위험한 표현을 줄인다.
5. 키워드 검색량, 경쟁도, 포화지수, 등급을 분석한다.
6. 썸네일과 워터마크까지 제작할 수 있게 한다.

제약:
- 구현 언어는 Python을 중심으로 한다.
- 웹 UI는 Streamlit을 사용한다.
- API 키는 코드에 직접 노출하지 않는다.
- 의료정보는 일반 안내이며 최종 검토는 의료진이 한다는 전제를 유지한다.
```

## Prompt 2. 기능 요구사항 도출
```text
위 프로젝트를 실제 제품 기획서처럼 기능군별 요구사항으로 나누어줘.
기능군은 콘텐츠 생성, 키워드 분석, 신뢰도 관리, 이미지/브랜딩, 데이터 관리, 배포/운영, 안전성으로 구분해줘.
각 요구사항은 ID, 기능군, 요구사항명, 상세 설명, 우선순위로 표를 만들어줘.
특히 키워드 등급, 포화지수, 스마트블록, 썸네일 제작, 워터마크 기능이 빠지지 않게 해줘.
```

## Prompt 3. 화면 설계 요청
```text
Streamlit 앱 기준으로 화면 설계서를 작성해줘.
필요 화면:
1. 메인 글 생성 화면
2. 키워드 분석 화면
3. 스타일 가이드 편집 화면
4. 레퍼런스 글 관리 화면
5. 썸네일 제작 화면
6. 워터마크 화면

각 화면마다 입력 항목, 처리 내용, 출력 결과, 사용자가 기대하는 행동을 표로 정리해줘.
```

## Prompt 4. Python/Streamlit 구현 구조 설계
```text
기능을 Python 파일 구조로 나누어줘.
현재 구조는 app.py, pages 폴더, src/naverblog 폴더, scripts 폴더로 구성한다.
각 파일이 담당할 책임을 정리하고, 모듈 간 데이터 흐름을 설명해줘.
```

## Prompt 5. 키워드 분석 기능 구현 방향
```text
네이버 블로그 마케팅용 키워드 분석 기능을 설계해줘.
필수 지표:
- 월간 PC/모바일 검색량
- 경쟁도
- 블로그 발행수
- 카페 발행수
- 콘텐츠 포화지수
- 키워드 등급 S/A/B/C/D
- 연관 키워드
- 주제 클러스터
- 해시태그
- 검색 트렌드
- 성별/연령대 인구통계
- 스마트블록 구성

각 지표가 병원 블로그 글 발행 전략에 어떻게 쓰이는지도 설명해줘.
```

## Prompt 6. 의료광고 표현 점검 로직
```text
병원 블로그 글에서 의료광고상 위험할 수 있는 표현을 점검하는 Python 로직을 작성해줘.
위험 표현 예시는 완치, 100%, 부작용 없음, 최고, 유일, 무조건이다.
각 표현이 왜 위험한지와 어떤 표현으로 바꾸면 좋은지 함께 출력해줘.
결과는 리스트 형태로 반환하고, 화면에는 표현/이유/대체 방향으로 보여줘.
```

## Prompt 7. 썸네일 제작 기능 설계
```text
병원 블로그용 썸네일 제작 화면을 설계해줘.
기능은 텍스트 입력, 제목/부제목 편집, 색상 선택, 배경 이미지 업로드, 정렬, 글자 크기 조절, 다운로드를 포함해줘.
UI는 사용자가 미리캔버스처럼 직관적으로 조작할 수 있게 구성해줘.
```

## Prompt 8. 구현 후 검증 요청
```text
구현된 Python/Streamlit 프로젝트를 검토해줘.
확인할 항목:
1. 문법 오류가 없는가
2. 주요 페이지가 import 가능한가
3. 의료광고 위험 표현 점검이 동작하는가
4. 키워드 분석 결과가 캐시될 수 있는가
5. 썸네일/워터마크 기능이 파일 출력까지 이어지는가
6. 배포 시 API 키가 코드에 노출되지 않는가
검증 결과를 테스트 시나리오 표로 정리해줘.
```
